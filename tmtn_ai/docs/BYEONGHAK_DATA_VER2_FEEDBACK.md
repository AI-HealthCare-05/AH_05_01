## 1. 전달 메시지

병학님, 데이터 ver2 작성해주셔서 감사합니다.

기존 AI 모델 개발 워크플로우 및 추가로 진행한 KNHANES 원시변수 감사 결과와 대조해봤습니다. 공식 이용지침서로 `HE_DM_HbA1c`, `HE_HP`의 의미와 연도별 코드값을 확인해주신 부분이 특히 도움이 됐습니다. 기존 산출물과 라벨이 동일하다는 재현성 확인, 성별을 임의로 매핑하지 않은 점, 운동 피처를 정의가 불명확한 상태에서 모델에 넣지 않은 점도 이후 데이터 계약에 반영하면 좋겠습니다.

다만 실제 모델 개발과 공개 검증으로 넘어가기 전에 아래 항목은 함께 기준을 확정할 필요가 있어 보입니다.

## 2. 데이터 ver2에서 반영할 사항

다음 내용은 기존 워크플로우 및 데이터 계약에 반영한다.

- 질병관리청 공식 원시자료 이용지침서를 기준으로 변수 의미와 코드값을 검증한다.
- 사용한 공식 문서의 출처, 버전 및 SHA-256을 기록한다.
- 기존 라벨 산출물과 재생성 결과가 동일한지 비교한다.
- 앱 성별 선택지를 KNHANES의 남성·여성 값으로 임의 변환하지 않는다.
- 정의가 확정되지 않은 운동 피처는 임의 생성하거나 대치하지 않는다.
- 허리둘레는 `measured_or_estimated` 정책을 적용하고 다음 메타데이터를 함께 저장한다.
  - `waist_value`
  - `waist_source`
  - `waist_estimator_version`
  - `input_snapshot_id`
- 현재의 코어 baseline 결과는 내부 비교 실험 자료로 활용한다.

## 3. 공동으로 수정·확정할 사항

### 3.1 2024년 데이터의 상태

데이터 ver2에서 2024년의 양성률과 모델 성능이 이미 산출됐기 때문에, 프로젝트 전체 기준으로 2024년은 더 이상 독립적인 최종 holdout으로 사용할 수 없다.

이번 원시변수 감사에서 2024년의 컬럼 구조만 확인하고 값은 열람하지 않았더라도, 이전 작업에서 2024년 결과가 공개됐다는 사실은 바뀌지 않는다.

권장 상태는 다음과 같다.

```yaml
2024_dataset_status: OPENED_TEMPORAL_EVALUATION
2024_independent_holdout_status: INVALIDATED
core_baseline_status: INTERNAL_RESEARCH_ONLY
independent_final_holdout: NOT_AVAILABLE
```

향후 검증 방향:

- 2019~2024년을 이용한 rolling temporal validation 또는 nested validation을 수행한다.
- 2024년 성능은 시간적 안정성 참고 결과로만 사용한다.
- 최종 공개 게이트는 향후 신규 연도 KNHANES 또는 별도 외부 데이터로 수행한다.
- 신규 최종 평가 데이터는 가능하면 모델 개발자와 분리된 담당자가 보관한다.
- 이미 확인한 2024년 결과를 바탕으로 반복 튜닝한 모델을 최종 검증 모델로 표현하지 않는다.

### 3.2 공식 생성변수와 primary label의 구분

공식 지침서로 변수 의미가 검증됐다는 것과 해당 변수를 제품의 primary target으로 승인하는 것은 별개의 문제다.

#### 당뇨병

`HE_DM_HbA1c`는 다음 정보를 포함하는 복합 질병 상태 변수다.

- 공복혈당
- HbA1c
- 의사진단
- 혈당강하제 또는 인슐린 치료

#### 고혈압

`HE_HP`는 다음 정보를 포함하는 복합 질병 상태 변수다.

- 수축기·이완기 혈압
- 항고혈압제 복용

기존 합의대로 측정값 기반 라벨을 주 라벨로 사용한다면 다음처럼 역할을 분리한다.

| 구분 | 용도 | 후보 정의 |
|---|---|---|
| Primary label | 모델의 주 학습·평가 타깃 | 공복혈당·HbA1c 또는 SBP·DBP 원측정값으로 직접 생성 |
| Comparator label | 민감도 분석 및 공식 통계 비교 | `HE_DM_HbA1c`, `HE_HP` |

상태 표기는 다음처럼 구분한다.

```yaml
official_label_code_semantics: VALIDATED
primary_target_contract: PENDING_JOINT_DECISION
```

다음 사항은 강호님·병학님이 함께 확정한다.

- 제품이 예측하려는 대상이 `현재 측정 이상`인지 `질환 보유 상태`인지
- 치료 중 측정값이 정상인 사람을 양성으로 볼지
- 공복시간 유효 기준
- HbA1c만 존재하는 대상자의 포함 여부
- 임신 대상자의 제외 여부
- 혈압 측정 회차 및 평균값 사용 규칙
- 당뇨 전단계·혈압 전단계를 주 타깃 또는 보조 타깃으로 둘지

### 3.3 운동 입력 계약

추가 원시변수 감사에서 다음 변수가 2019~2024년 자료에 존재하는 것으로 확인됐다.

| 개념 | KNHANES 변수 | 비고 |
|---|---|---|
| 유산소 세부 문항 | `BE3_71~94` | 직장·이동·여가 신체활동 포함 |
| 근력운동 일수 | `BE5_1` | 0·1·2·3·4·5일 이상 범주 |
| 유산소 기준 충족 여부 | `pa_aerobic` | 이진 생성변수 |
| 별도 걷기 문항 | `BE3_31~33` | 공식 `pa_aerobic` 산식과 별도 관리 필요 |

따라서 아래 세 가지 피처 세트를 비교한다.

```text
M0: 나이 + 성별 + 키 + 몸무게
M1: M0 + pa_aerobic + 근력운동 일수
M2: M0 + 유산소 환산 분/주 + 근력운동 일수
```

운동 피처를 확정하기 전에 다음을 먼저 결정한다.

- 앱이 `여가 운동`을 물을지 `직장·이동을 포함한 전체 신체활동`을 물을지
- 앱 질문 문구와 KNHANES 학습 피처가 같은 개념인지
- 공식 SAS의 문항별 skip logic과 결측 처리 방식
- `BE5_1=6`을 숫자 6일이 아니라 `5일 이상` 순서형 범주로 처리하는 방식
- 걷기 문항을 공식 지표와 분리한 별도 실험 피처로 사용할지

M2가 M0·M1보다 연도별·성별·연령별로 안정적인 개선을 보일 때만 6입력 모델을 주 모델로 채택한다.

### 3.4 허리둘레 추정값과 질환 모델 연결

질환 모델이 운영 단계에서 추정 허리둘레를 사용한다면 학습 단계에서도 같은 조건을 재현해야 한다.

권장 방식:

1. 개발 학습 데이터를 여러 fold로 나눈다.
2. 각 fold 외부 데이터로 허리둘레 모델을 학습한다.
3. 제외된 fold에 대해 허리둘레를 예측한다.
4. 이렇게 생성한 OOF 허리둘레 추정값을 질환 모델의 학습 피처로 사용한다.
5. 검증·테스트 데이터는 해당 데이터에 적합하지 않은 허리둘레 모델로 예측한다.

피해야 할 방식:

- 실측 허리둘레로 질환 모델을 학습하고 운영에서는 추정값을 입력하는 방식
- 같은 행을 학습한 허리둘레 모델의 예측값을 다시 그 행의 질환 모델 입력으로 사용하는 방식
- 허리둘레 추정 모델 버전 없이 값만 저장하는 방식

### 3.5 baseline 평가 항목 보완

현재 ROC-AUC·PR-AUC는 baseline 비교 자료로 활용하되, 제품이 연속형 0~1 확률을 제공하려면 다음 평가를 추가한다.

- ROC-AUC
- PR-AUC
- Brier score
- Log loss
- Calibration curve
- Calibration intercept·slope
- 가중 성능과 비가중 성능
- 성별·연령별 하위집단 성능
- 랜덤 8:2와 연도 기반 검증 결과 비교
- 동일 입력·동일 버전의 재현성

`단일 피처 AUC < 0.85`만으로 누설이 없다고 확정하지 않는다. 다음 검증을 별도로 수행한다.

- 타깃 또는 타깃 산식에서 파생된 변수 차단 목록
- 피처별 출처와 생성 시점 감사
- 전처리·결측 대치·보정기의 train-only fit 확인
- split 간 ID 중복 검사
- 허리둘레 추정값의 OOF 생성 확인

## 5. 제안하는 역할 분담

역할은 고정 소유권이 아니라 1차 담당과 상호 검토 방식으로 운영한다.

| 작업 | 1차 담당 제안 | 공동 검토 |
|---|---|---|
| 공식 변수·코드·연도별 변경 근거 정리 | 병학님 | 강호님 |
| 측정 기반 라벨 산식 구현 | 병학님 | 강호님 |
| 6입력 계약 및 M0·M1·M2 실험 설계 | 강호님 | 병학님 |
| 허리둘레 추정 모델 및 OOF 파이프라인 | 강호님 | 병학님 |
| 당뇨·고혈압 확률 모델 | 공동 | 상호 코드 리뷰 |
| Calibration 및 하위집단 평가 | 공동 | 상호 결과 검증 |

## 7. 핵심 요약

데이터 ver2의 공식 변수 의미 검증과 baseline 실험은 이후 개발에 활용한다. 다만 2024년은 이미 결과가 확인되어 독립적인 최종 holdout으로 사용할 수 없으며, `HE_DM_HbA1c`와 `HE_HP`는 진단·치료가 포함된 복합 라벨이므로 측정값 기반 primary label과 구분해야 한다.

운동 원문항이 확인됐으므로 M0·M1·M2 비교 계약을 수립하고, 허리둘레 추정값을 질환 모델에 사용할 때는 OOF 방식으로 생성한다. 위 기준이 공동 승인된 뒤 데이터 계약을 v0.2로 갱신하고 모델 학습 단계로 이동한다.
