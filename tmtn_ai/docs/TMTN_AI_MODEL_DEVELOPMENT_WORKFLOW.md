# 틈튼(TMTN) AI 모델 개발 워크플로우

> 문서 목적: 박강호·병학님의 데이터/AI 작업 기준을 통일하고, KNHANES 2019~2024를 이용한 데이터 계약부터 모델 공개까지의 순서와 담당자를 명확히 한다.
>
> 현재 상태: **원시 스키마·값 감사, 운동 전처리, 측정 조화, 2019~2022 canonical ETL 집계 확인 완료**. canonical ETL은 기술 검증을 통과했고 공동 승인 대기 상태다. `data_contract_v0_3`의 `do_not_train: true`는 유지되며 실제 KNHANES 분할·EDA·학습은 아직 시작하지 않는다.

---

## 1. 최종 목표와 P0 범위

### 최종 목표

앱에서 받는 최소 입력과 검증된 서브모델 출력을 이용해 다음 결과를 제공한다.

1. 허리둘레 등 건강 지표 추정 서브모델
2. 당뇨·고혈압 위험을 각각 `0~1`로 출력하는 보정된 질환별 모델
3. 별도 검증을 통과한 경우에만 질환별 결과를 단일 참고 점수인 틈틈지수로 환산

### P0 모델 범위

- 확정 서브모델: 허리둘레 추정
- 확정 질환 모델: 당뇨, 고혈압
- 틈틈지수: 종합 공식 검증 전까지 개발·노출 보류
- 행동 데이터: KNHANES에 챌린지 수행 데이터와 이후 질환 결과가 없으므로 P0 질환 확률을 변화시키는 학습 피처로 사용하지 않음

> 행동 데이터는 초기에는 수행률·연속 실천 등 별도 행동 지표로 저장한다. 질환 확률 또는 틈틈지수에 반영하려면 종단 데이터와 별도 검증이 필요하다. 검증 전 임시 평균이나 임의 가중치는 사용하지 않는다.

## 2. 고정 원칙

1. **2024년은 이미 개봉된 진단용 temporal 자료**이며 독립 holdout으로 부르거나 그 결과에 맞춰 튜닝하지 않는다.
2. 2019~2021년은 내부 개발·반복 층화 CV, 2022년은 시간 검증, 2023년은 잠금 내부 테스트로 사용한다. 최종 공개 평가는 향후 신규 연도 또는 외부 자료로 수행한다.
3. 원자료 컬럼을 바로 모델에 넣지 않고, 연도별 정의·단위·코드·결측값을 통일한 canonical modeling table을 만든다.
4. 전처리기의 결측 대치·스케일링·인코딩·피처 선택은 train에만 fit한다.
5. 허리둘레 추정값을 당뇨·고혈압 모델에 넣을 때 train 내부 OOF(out-of-fold) 예측값을 사용한다. 실측 허리둘레를 그대로 넣어 학습하지 않는다.
6. 모든 산출물은 데이터 snapshot, 피처 계약 버전, 모델 버전, calibration 버전, 코드 해시와 연결한다.
7. KNHANES의 복합표본설계를 고려해 비가중 성능과 적절한 표본가중 평가를 함께 보고한다.
8. 건강 결과는 진단이 아닌 참고 정보로 표현하고, 안전 문구 승인 전 공개하지 않는다.

## 단계 2. 데이터 계약 확정

### 2.1 앱 입력 계약

분할기의 6개 입력 계약은 `age_years`, `sex_code`, `height_cm`, `weight_kg`, `leisure_aerobic_moderate_equivalent_min_week`, `strength_days_week`로 확정했다.

권장 모델 입력 계약:

| 피처 | 권장 이름 | 단위/값 | 비고 |
|---|---|---|---|
| 나이 | `age_years` | 만 나이, year | 성인 범위 확정 |
| 성별 | `sex_code` | 고정 코드 | 앱·KNHANES 코드 매핑 |
| 키 | `height_cm` | cm | 허용 범위 확정 |
| 몸무게 | `weight_kg` | kg | 허용 범위 확정 |
| 유산소 | `aerobic_moderate_equivalent_min_week` | 분/주 | 고강도 1분을 중강도 2분으로 환산 |
| 근력 | `strength_days_week` | 0,1,2,3,4,5+ | `BE5_1`과 정렬 |

유산소 환산식 후보:

```text
aerobic_moderate_equivalent_min_week
= 주당 중강도 활동 분
+ 주당 이동 활동 분
+ (주당 고강도 활동 분 × 2)
```

앱이 여가 운동만 물을 경우에는 KNHANES도 여가 변수만 사용해야 한다. KNHANES 전체 신체활동을 사용한다면 앱 문구도 일·이동·운동을 모두 포함한다고 명시한다.

### 2.2 운동 변수가 일부 연도에 없을 때의 결정 순서

1. 원자료에 세부 문항이 있으면 통합 데이터를 다시 생성한다.
2. 일부 연도에만 있으면 공통 연도 모델과 전체 연도 4입력 모델을 별도로 비교한다.
3. `pa_aerobic`만 있으면 앱 입력도 동일한 기준 충족 여부로 이진화한 fallback 모델만 만든다.
4. 운동 피처가 안정적 개선을 보이지 않으면 건강 예측 모델에서는 제외하고 챌린지 추천·행동 기록에만 사용한다.
5. 이진값으로 세부 빈도·시간을 추정하거나 임의 분포로 대치하지 않는다.

### 2.3 비교할 피처 세트

```text
F0: 나이 + 성별 + 키 + 몸무게
F1: F0 + pa_aerobic + 근력운동 일수
F2-total: F0 + 전체 신체활동 환산 분/주 + 근력운동 일수
F2-leisure: F0 + 여가 유산소운동 환산 분/주 + 근력운동 일수
```

P0 앱 입력은 `F2-leisure`와 정렬한다. `F2-total`은 연구 비교용이며, F2가 연도별·성별·연령별로 안정적으로 개선될 때만 최종 6입력 모델에 채택한다.

### 2.4 라벨 계약

| 모델 | 라벨 후보 | 반드시 확정할 사항 |
|---|---|---|
| 허리둘레 | 실측 허리둘레 | 단위, 측정 실패, 임신 등 제외 기준 |
| 당뇨 | 공복혈당·HbA1c 측정 이상 | 공복 유효시간, 결측·검사 조화, 경계값 재현 |
| 고혈압 | 수축기·이완기 혈압 측정 이상 | 사용할 측정 회차·평균식, 기기 조화, 경계값 재현 |

자가진단 문항명은 연도별 변경 가능성이 있으므로 주 라벨로 사용하지 않는다. Primary는 `현재 측정 이상`으로 확정했으므로 약물치료 중이라도 현재 측정값이 기준 미만이면 primary에서는 음성으로 처리한다. 진단·복약을 포함한 공식 생성변수는 comparator·민감도 분석에만 사용한다.

### 처리 순서

2. 성인 cohort 필터링

7. 질환 라벨 생성

### 개발 데이터에서 확인할 품질 항목

- 행 수와 연도별 대상자 수

## 단계 5. 개발 분할 확정

### 분할 구조

```text
Random 개발 보조 비교
2019~2021 → stratified random train 80% / validation 20%

Primary temporal 설계
2019~2021 → 반복·층화 CV 개발
2022      → temporal validation
2023      → locked internal test
2024      → 현재 파이프라인 사용 금지

최종 공개 게이트
향후 신규 KNHANES 연도 또는 외부 cohort → independent final evaluation
```

Random 8:2와 내부 CV의 개발 행이 서로 겹치는 것은 보조 평가 설계를 비교하기 위한 것이며 오류가 아니다. 2022·2023·2024는 random 8:2 모집단에 넣지 않는다.

### 모델 선택 규칙

- 하이퍼파라미터 탐색은 train 내부 CV에서 수행
- random validation은 2019~2021 내부 일반화 보조 점검
- 2022 temporal validation은 연도 이동 안정성 및 선택 단계
- 2023 locked internal test는 튜닝 금지 평가
- 2024는 현재 분할·모델링 파이프라인에서 사용 금지

---

## 단계 6. EDA와 베이스라인

### 먼저 만들 모델

1. Dummy baseline
2. 선형/로지스틱 baseline
3. 트리 기반 baseline

### 비교 원칙

- 허리둘레: MAE, RMSE, MAPE 또는 상대오차, 잔차 분포
- 질환 확률: AUROC, AUPRC, Brier score, log loss, calibration slope/intercept
- 표본가중·비가중 지표를 구분해 기록
- 성별·연령대 등 하위집단별 성능과 오차 함께 기록

## 단계 7. 허리둘레 서브모델 개발

### 실험 순서

1. 4입력 F0 개발
2. 이진 운동 피처 F1 비교
3. 연속 운동량 F2-total·F2-leisure 비교
4. 선형·규제회귀·트리 부스팅 비교
5. 연도별·하위집단별 MAE 확인
6. 실측값 입력 시 추정값보다 실측값을 우선하는 서비스 계약 정의

### 산출물

- 학습 pipeline
- 모델 artifact
- 피처·모델 버전
- 허리둘레 추정/실측 구분 저장 규칙
- model card와 실패 fallback

## 단계 8. 당뇨·고혈압 확률모델 개발

### 누설 방지 구조

```text
train fold의 6개 입력
    ↓
다른 fold에서 학습한 허리둘레 모델
    ↓
OOF 허리둘레 추정값
    ↓
당뇨/고혈압 확률모델 학습
```

2022·2023·2024에는 각각 해당 평가 데이터로 학습하지 않은 허리둘레 모델을 적용한다. 질환 파이프라인은 직접 입력만 쓰는 `D0`, OOF 추정 허리둘레를 더한 `D1`, 향후 승인 서브모델을 더한 `D2`로 구분한다.

### 출력

- 당뇨 위험 참고값 `0~1`
- 고혈압 위험 참고값 `0~1`
- calibration 버전
- 입력 snapshot·모델 버전·출력 생성시각

## 단계 9. 공개 게이트

| 게이트 | 확인 내용 | 통과 기준 문서화 |
|---|---|---|
| 누설 | 라벨·실측 대체값·평가 데이터가 학습 과정에 들어갔는가 | 필수 |
| 독립 holdout | 향후 신규 연도 또는 외부 자료가 개발 전 미사용인가 | 공개 전 필수 |
| 시점 안정성 | 2022 validation·2023 locked test 성능 저하가 허용 범위 이내인가 | 필수 |
| Calibration | 확률과 실제 빈도가 일치하는가 | 필수 |
| 하위집단 | 성별·연령 등에서 과도한 성능 저하가 없는가 | 필수 |
| 재현성 | 동일 입력·버전에서 동일 결과가 나오는가 | 필수 |
| 안전 문구 | 진단·치료로 오해되지 않는가 | 필수 |
| QA | API·DB·화면·fallback이 계약과 일치하는가 | 필수 |

게이트 기준값은 2023 잠금 테스트와 향후 최종 평가 전에 정한다. 2024 결과는 진단 근거로만 기록하며 이에 맞춰 현재 버전을 재튜닝하지 않는다.
