# KNHANES 데이터 ver3 검토 피드백 및 후속 진행 방향

> 작성일: 2026-08-24  
> 작성자: 박강호  
> 상태: 임상·신체활동 지침 대조 완료, 데이터 계약 반영 예정

병학님, ver3 내용 확인했습니다. 정리해주신 방향을 기반으로 다음 5개 참고 지침을 추가로 대조했습니다.

- 2025 당뇨병 진료지침
- 2022년 고혈압 진료지침
- 2026년 고혈압 진료지침
- WHO Guidelines on Physical Activity and Sedentary Behaviour
- 한국인을 위한 신체활동 지침서 개정판

검토 결과 큰 방향은 유지하되, 모델 출력의 의미와 임신자 처리, 운동 입력 정의를 아래와 같이 보완해서 진행하기로 했습니다.

## 1. Primary 라벨 정의

공복혈당·HbA1c와 혈압 실측값 기반 라벨을 primary로 유지합니다.

다만 KNHANES 자료는 단일 방문 측정이므로 결과를 `당뇨병·고혈압 진단` 또는 `미래 발병 위험`으로 해석하지 않고, **현재 단일 방문 측정 이상 가능성**으로 정의합니다.

### Primary 라벨

```text
당뇨 측정 이상:
공복시간이 유효한 대상자에서
공복혈당 >= 126 mg/dL OR HbA1c >= 6.5%

혈압 측정 이상:
SBP >= 140 mmHg OR DBP >= 90 mmHg
```

### Comparator 및 민감도 분석

- 진단·복약을 포함한 `HE_DM_HbA1c`, `HE_HP`는 comparator 및 민감도 분석에 사용합니다.
- 치료 중 현재 측정값이 기준 미만인 대상자는 측정 이상 primary에서는 음성으로 처리합니다.
- 동일 대상자라도 질환 상태 comparator에서는 질환 보유로 구분합니다.
- 모델 출력과 제품 문구에는 임상적 진단 또는 미래 발병 확률로 오해될 표현을 사용하지 않습니다.

## 2. 임신자 처리

임신자는 일반 성인 대상의 허리둘레·당뇨·고혈압 P0 모델 cohort에서 모두 제외합니다.

다만 모델에서 제외하는 것과 앱 서비스를 전면 제한하는 것은 구분합니다.

- 앱에서는 임신 여부를 모델 피처가 아닌 `eligibility/safety field`로 확인합니다.
- 임신 중인 사용자에게 일반 성인용 허리둘레 추정값과 질환별 점수를 제공하지 않습니다.
- API는 `unsupported_population` 또는 이에 준하는 상태를 반환합니다.
- 생활습관 챌린지는 임신부를 일괄 제외하지 않고, 안전 문구와 적절한 대체 경로를 제공합니다.
- 값 수준 감사에서 `HE_prg`, `HE_dprg`의 실제 코드, 결측, 연도별 일관성을 확인합니다.

## 3. 앱 유산소 입력과 KNHANES 운동 피처

앱의 유산소 입력은 **여가 목적 유산소운동**으로 한정하고, KNHANES의 여가 중강도·고강도 운동 문항과 개념을 정렬합니다.

단순히 `주당 일수 × 회당 운동시간`만 계산하면 고강도 가중치를 반영할 수 없으므로 다음 세 항목을 받는 방향으로 설계합니다.

```text
앱 원시 응답
1. 주당 유산소운동 일수
2. 회당 평균 운동시간
3. 대표 운동강도: 중강도 / 고강도
```

모델 입력값은 다음과 같이 한 개의 파생 피처로 환산합니다.

```text
중강도 선택:
주당 일수 × 회당 평균 운동시간

고강도 선택:
2 × 주당 일수 × 회당 평균 운동시간
```

최종 피처명은 다음을 사용합니다.

```text
leisure_aerobic_moderate_equivalent_min_week
```

추가 원칙은 다음과 같습니다.

- `MET-분`이라는 명칭은 사용하지 않습니다.
- `pa_aerobic` 이진값에서 운동 빈도나 시간을 역추정하지 않습니다.
- `F2-total`은 직장·이동·여가를 포함한 연구 비교용 피처 세트로만 유지합니다.
- 앱의 P0 주 후보는 여가 운동과 정렬된 `F2-leisure`입니다.
- 온보딩 질문 수를 늘릴 수 없다면, 강도 가중치를 제거한 별도의 비가중 여가 운동시간 피처를 KNHANES에서도 동일하게 만들어 비교해야 합니다.

## 4. 피처 세트와 질환 파이프라인 명칭

입력 피처 세트와 질환 모델 구조에 같은 명칭을 사용하지 않도록 다음과 같이 구분합니다.

### 입력 피처 세트

```text
F0 = 나이 + 성별 + 키 + 몸무게

F1 = F0 + pa_aerobic + 근력운동 일수

F2-total = F0
           + 전체 신체활동 중강도 환산 분/주
           + 근력운동 일수

F2-leisure = F0
             + 여가 유산소운동 중강도 환산 분/주
             + 근력운동 일수
```

### 질환 모델 파이프라인

```text
D0 = 선택한 F 피처 세트만 사용

D1 = D0 + OOF 추정 허리둘레

D2 = D1 + 향후 별도 검증을 통과한 서브모델 출력
```

BMI는 키와 몸무게로 서버에서 재계산하는 파생값이며 독립적인 앱 입력 개수에는 포함하지 않습니다.

P0의 주 후보는 `F2-leisure + D1`이지만, 값 수준 감사와 모델 비교검증이 끝나기 전에는 최종 모델로 확정하지 않습니다. 선택형 온보딩을 건너뛴 사용자를 위해 `F0`는 fallback 후보로 유지합니다.

## 5. 데이터 분할과 검증 연도

검증 구조는 다음과 같이 고정합니다.

```text
2019~2021
- 내부 개발
- 반복·층화 교차검증
- 랜덤 8:2 보조 비교

2022
- temporal validation

2023
- locked internal test
- 결과 확인 후 현재 버전 재튜닝 금지

2024
- opened diagnostic evaluation
- 이미 개봉된 자료이므로 독립 holdout으로 사용하지 않음
- 결과 기반 재튜닝 금지

향후 신규 KNHANES 연도 또는 외부 cohort
- 최종 독립 공개 평가
```

랜덤 8:2는 시간 검증을 대체하지 않으며, 2019~2021 개발 자료 안에서만 보조 비교로 사용합니다. 2022·2023·2024는 랜덤 분할 모집단에 포함하지 않습니다.

## 6. 현재 단계와 학습 금지 원칙

현재는 위 결정을 반영한 `data_contract_v0_3`과 모델 개발 워크플로우를 정리한 뒤, **2019~2023 값 수준 감사**로 넘어가는 단계입니다.

다음 조건을 충족하기 전까지 `do_not_train: true`를 유지합니다.

- 값 수준 감사 완료
- 변수별 특수코드·유효범위·skip logic 확정
- 라벨과 cohort 생성 규칙 확정
- 앱 운동 입력 문구 및 강도 질문 기획 승인
- 임신 여부 eligibility 처리 승인
- 강호·병학 데이터/AI 공동 승인

## 7. 병학님께 우선 확인을 요청드리는 항목

값 수준 감사 단계에서 다음 항목을 우선 확인해주시면 좋겠습니다.

### 임신 및 cohort

- `HE_prg`, `HE_dprg`의 실제 코드와 연도별 일관성
- 두 변수 간 모순 또는 결측 조합
- 허리둘레·당뇨·고혈압 cohort에서 사용할 공통 임신 제외 규칙

### 운동 변수

- 여가 중강도·고강도 운동 문항의 연도별 특수코드
- 문항별 구조적 비해당과 무응답 구분
- 공식 branch-aware skip logic 재현
- 공식 `pa_aerobic` 생성식과 재구성 값의 행 수준 일치도
- 중강도·고강도 일수·시간·분의 불가능 조합 탐지 규칙

### 당뇨·고혈압 라벨

- 공복시간·공복혈당·HbA1c 라벨 생성 가능 cohort 수
- HbA1c 원자료와 2022년 이후 연구자 전환값 비교 방식
- `HE_sbp`, `HE_dbp`와 2·3차 측정 평균의 일치도
- 혈압계 변경 전후 원자료·연구자 전환값 비교 방식
- 연도별·성별·연령별 라벨 양성률과 결측률

### 복합표본 설계

- `wt_itvex`, `kstrata`, `psu`의 값 유효성
- 모델 평가 시 가중·비가중 결과를 함께 보고할 수 있는지
