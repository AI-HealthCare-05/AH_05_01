# KNHANES 2019~2024 원시자료 변수 감사표

> 상태: 진행 중  
> 목적: 실제 값·분포·성능을 보기 전에 연도별 변수의 존재, 정의, 단위, 응답코드와 조사대상을 확정한다.  
> 보안 원칙: 2024는 컬럼명과 공식 코드북만 확인하며 행 예시·값 개수·결측률·라벨 통계를 확인하지 않는다.

## 1. 현재 결론

- 통합 데이터의 `aerobic_activity`는 이진값이므로 유산소 빈도나 운동량을 복원할 수 없다.
- 제9기 공식 이용지침서에는 유산소 활동의 여부·일수·시간·분 문항과 근력운동 일수 `BE5_1`이 존재한다. 이는 **문서상 확인**이며 실제 연도 파일의 컬럼 존재 여부는 스키마 감사로 별도 확인한다.
- 따라서 원자료에 세부 운동 문항이 실제 포함돼 있는지 연도별로 확인하고 통합 ETL을 다시 만드는 것이 우선이다.
- 현재 split YAML의 `aerobic_frequency`, `strength_frequency`는 임시 이름이며 이 감사가 완료되기 전 실행하지 않는다.

### 제9기 `pa_aerobic` 생성식 요약

```text
vigorous_min_week
= 일 관련 고강도 분/주 + 여가 고강도 분/주

moderate_transport_min_week
= 일 관련 중강도 분/주 + 여가 중강도 분/주 + 이동 활동 분/주

moderate_equivalent_min_week
= moderate_transport_min_week + (vigorous_min_week × 2)

pa_aerobic = 1 if
  moderate_transport_min_week >= 150
  or vigorous_min_week >= 75
  or moderate_equivalent_min_week >= 150
else 0
```

이 생성식은 제9기 공식 지침서 기준 요약이다. 제8기에도 같은 문항·코드·생성 조건이 적용됐는지 확인한 후 canonical ETL에 반영한다.

## 5. 운동 피처 결정 기록

### 후보

```text
M0 = 나이 + 성별 + 키 + 몸무게
M1 = M0 + pa_aerobic + strength_days_week
M2 = M0 + aerobic_moderate_equivalent_min_week + strength_days_week
```

### 결정 전 질문

- [ ] 앱은 일·이동·여가를 합친 전체 신체활동을 묻는가?
- [ ] 앱은 여가 목적의 운동만 묻는가?
- [ ] 앱에서 주당 일수와 회당 시간을 받아 분/주로 환산할 수 있는가?
- [ ] 2019~2024에 동일한 운동 문항과 코드가 존재하는가?
- [ ] M2가 M0보다 연도별·하위집단별로 안정적으로 개선되는가?
