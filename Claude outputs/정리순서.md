## 1단계 · .gitignore 먼저 (이게 먼저여야 합니다)

`android/.gitignore` 를 첨부한 `android_gitignore.txt` 내용으로 교체하세요.

Gradle 홈(`GRADLE_USER_HOME`)이 프로젝트 폴더 안에 잡혀 있어서 이런 것들이 들어와 있습니다.

| 폴더 | 용량 | 정체 |
|---|---|---|
| `android/caches` | 1.2G | 의존성 캐시 |
| `android/jdks` | 502M | Gradle이 받아둔 JDK |
| `android/wrapper` | 151M | Gradle 배포본 |
| `daemon` `native` `kotlin-profile` `tools` | 1M 미만 | 데몬 로그 등 |

전부 추적은 안 되고 있지만 **무시 목록에도 없어서**, `git add -A` 한 번이면 통째로 들어갑니다. 그래서 이 단계가 먼저입니다.

```bash
cd ~/PycharmProjects/AH_05_01
# android/.gitignore 를 첨부 파일 내용으로 교체한 뒤
git status --porcelain | grep '^??'
# → android/caches/ 같은 줄이 사라졌는지 확인
```

## 4단계 · 줄바꿈 정리 (반드시 별도 커밋)

`.kt` 125개 중 **100개가 CRLF, 25개가 LF** 로 섞여 있습니다. 이 상태에서는 한 줄만 고쳐도 diff에 파일 전체가 바뀐 것으로 나옵니다. 실제로 `feature/11` 과 비교했을 때 4,098줄 추가 / 4,170줄 삭제로 잡혔는데, **줄바꿈을 무시하면 실제 변경은 148줄**이었습니다.

3단계까지 커밋을 끝낸 **뒤에** 하세요. 안 그러면 진짜 변경과 줄바꿈 변경이 한 커밋에 섞여서 구분이 안 됩니다.

```bash
cd ~/PycharmProjects/AH_05_01
# .gitattributes 를 첨부한 gitattributes.txt 내용으로 교체한 뒤
git add --renormalize .
git commit -m "chore: 줄바꿈 LF로 통일 (.gitattributes)"
```

이 커밋은 100개 파일이 바뀐 것으로 나오지만 **내용 변경은 0줄**입니다. 커밋 메시지에 그렇게 적어두면 리뷰할 때 헷갈리지 않습니다.

## 지금은 손대지 말 것

**`tuntun_peer_bridge/` 의 26MB joblib.** `.git` 이 52MB인 이유가 이겁니다(`waist_model.joblib` 26MB + 당뇨 3.4MB + 고혈압 2.3MB). 히스토리에서 빼려면 전체 재작성이 필요하고, 그러면 팀원 전원이 다시 clone해야 합니다. **21일 배포 전에 할 일이 아닙니다.** 배포 끝나고 정리하시면 됩니다.

**`GRADLE_USER_HOME` 원위치.** Gradle 홈을 `~/.gradle` 로 되돌리면 프로젝트가 2.2GB → 400MB가 되지만, Android Studio 설정을 바꾸고 전체 재빌드를 해야 합니다. 이것도 배포 후에.
