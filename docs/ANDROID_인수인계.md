### 디자인 시스템

`designsystem/` 9개 파일에 토큰으로 잠가 뒀습니다.

- 색은 `TmtnColor.*`, 글자는 `TmtnText.*` **로만** 씁니다 → 현재 하드코딩된 색 **0개**
- 주황 `#FF7A1A` 은 "오늘"에만. 완료·실천·주 버튼은 전부 먹색
- 기록 달력은 색만이 아니라 **선 종류**로도 갈라 둠 (실선 = 쉼, 점선 = 미완료)
- 카드 그림 전용 색은 `TmtnCardArt.kt` 로 **완전히 분리** — 화면 팔레트와 섞이지 않음

### 카드 앞면 (2026-08-31 완료)

브랜드 시안 최종 채택안 `04 틈 노트` 를 **Compose 네이티브**로 옮겼습니다. WebView 도, 카드 통이미지도 쓰지 않습니다.
읽는 순서는 시안 그대로 — 오늘의 운세 → 행운의 행동 → 위치 → 숫자 → 오늘의 한 줄.
재료는 오른쪽 위 스탬프 한 곳에서만 바뀌므로 **카드 200장에 그대로 늘어납니다.**

## 2. 다음에 할 일

### 🔴 P0 — 데모 전에 반드시

#### P0-1. 미션이 실시간으로만 끝난다

**증상.** 자가 수행 미션은 초를 진짜로 1초씩 셉니다. 완료 버튼이 `enabled = vm.reachedGoal` 로 잠겨 있어서, "20분 잠자리 준비" 카드가 뽑히면 **진짜 20분을 기다려야** 완료됩니다.

미션 200개 구성:

| 타입 | 개수 | 데모 |
|---|---:|---|
| `SELF_CHECK` | 125 | ✅ 즉시 완료 |
| `SELF_TIMER` | 42 | ❌ 실시간 대기 |
| `MODEL_*` | 33 | 모델이 임시 구현 |

카드는 무작위로 뽑히므로 **5번에 1번꼴로 20분짜리에 걸립니다.** 심사 중에 걸리면 그대로 끝입니다.

**할 일.** `[DEMO]` 마커를 단 배속 스위치(1초 = 1분). 내 정보 탭 맨 아래에 이미 "데모 데이터 초기화" 가 있으니 그 옆이 자연스럽습니다.

**착수 지점.** `ui/mission/MissionRunViewModel.kt:105` 의 `delay(1000)` / `selfSeconds += 1`

#### P0-2. 완료 → 댐 성장 → 달력 반영을 아직 끝까지 못 돌려 봤다

P0-1 때문에 **미션을 완료까지 돌려본 적이 없습니다.** 코드상 `complete()` → `records` 갱신은 이어져 있지만 **실기기 확인은 안 된 상태**입니다.

P0-1 을 넣으면 이것도 같이 확인됩니다. 확인할 것:

- 완료 후 기록 달력에 **먹색 꽉 찬 원**이 찍히는가
- 댐 탭 재료 개수가 **+1** 되는가
- 홈 "이번 주" 점이 채워지는가
- 앱을 껐다 켜도 남는가

#### P0-3. 홈 오른쪽 위 "알림" 버튼이 죽어 있다

눌러도 아무 일도 안 일어납니다. 빈 람다입니다.

```kotlin
TmtnTopBar(title = "틈튼", actionLabel = "알림", onAction = { })
```

**착수 지점.** `ui/home/HomeScreen.kt:53`

**할 일.** 알림함(B13/B15)을 만들거나, 못 만들 거면 **버튼을 빼세요.** 데모에서 누가 누릅니다.

## 4. 함정 — 모르면 시간 날립니다

### 앱이 백엔드 몫을 임시로 들고 있다

서버 API 가 아직 없어서 `data/TmtnStore.kt`(SharedPreferences)가 DB 노릇을 합니다. 날짜 키로 저장합니다 — `rest_<날짜>` `swap_<날짜>` `note_<날짜>` `fit_<날짜>`.

이 둘은 **CLAUDE.md 가 서버에서 세라고 못박아 둔 값**입니다:

- **쉼 주 2회 카운트** — 지금은 기기 로컬. 기기를 바꾸면 초기화됩니다
- **하루 1회 미션 교체** — 같은 문제

API 를 붙일 때 **`data/` 아래부터** 보세요. `ui/` 와 `designsystem/` 은 거의 안 건드려도 되게 갈라 뒀습니다.

### `[DEMO]` / `[DEMO-MODEL]` 마커 규약

데모용 문구·값에는 전부 마커를 달아 뒀습니다. 규칙은 [`DEMO_걷어내기.md`](DEMO_걷어내기.md).
**이걸 모르면 데모용 표시를 진짜 기능으로 착각합니다.**

`[DEMO-MODEL]` 은 진짜 모델을 넣고 `ModelSlot.info.isPlaceholder = false` 로 두면 **저절로 사라집니다. 코드를 지우지 마세요.**

### 모델 3종은 전부 임시 구현

허리둘레 · 행동인식 · 틈튼지수 모두 자리만 잡혀 있습니다.
교체 지점은 **`domain/ml/ModelRegistry.kt` 한 파일**입니다. 화면 코드는 건드릴 필요 없습니다.

### Compose 음수 패딩은 앱을 죽인다

카드 앞면에서 한 번 밟았습니다. `IllegalArgumentException: Padding must be non-negative` 가 뜨고 **바로 종료**됩니다. 빌드는 통과하므로 실기기로만 잡힙니다.

안쪽 여백을 뺄셈으로 만들지 말고 **바깥을 적게 주고 안쪽에서 더 들이는** 방향으로 짜세요.

### 다이얼로그에 `TmtnShape.Sheet` 를 쓰지 말 것

`Sheet` 는 바텀시트용이라 **위 두 귀만** 둥급니다. 화면 한가운데 뜨는 다이얼로그에 쓰면 아래가 각져 어색합니다.
다이얼로그는 **`TmtnShape.Dialog`** 입니다.

## 6. 새 화면을 만드는 순서

**Figma 링크만으로는 화면을 만들 수 없습니다.** Figma 는 "어떻게 생겼나"만 알려 주고,
**무슨 값이 들어가고 · 언제 어떻게 갈라지고 · 어디로 넘어가는지**는 알려 주지 않습니다.
그 셋이 실제 작업량의 대부분입니다. 아래 순서대로 하세요.

### 1단계 — 무엇을 만들지 확정한다

[`design-v5/index.html`](design-v5/index.html) 을 브라우저로 엽니다. 화면 107장이 A~H 로 묶여 있고,
**코드(A01, B06…)를 누르면 그 화면의 Figma 가 바로 열립니다.** 이미지가 아니라 링크라서 항상 최신입니다.

같은 줄의 [`design-v5/SCREENS.csv`](design-v5/SCREENS.csv) 에 **문구가 이미 정해져 있습니다.**

| 열 | 뜻 |
|---|---|
| `appbar` | 앱바 제목 |
| `primary_cta` | 주 버튼 문구 |
| `bottom_nav` | `Y` 면 하단 탭이 보이는 화면 |
| `overlay` | 값이 있으면 전체 화면이 아니라 시트·다이얼로그 |

> **문구를 새로 짓지 마세요.** CSV 에 있으면 그대로 씁니다.
> 화면마다 말이 달라지는 게 이 앱에서 제일 티 나는 흠입니다.

### 2단계 — Figma 에서 볼 것과, 보고도 베끼면 안 되는 것

**볼 것**

- 위에서 아래로 **무엇이 먼저 오는지** (읽는 순서)
- 무엇이 카드로 묶여 있고 무엇이 목록인지
- 전체 화면인지, 아래에서 올라오는 시트인지, 가운데 뜨는 다이얼로그인지
- 버튼이 몇 개고 그중 **무엇이 주 버튼인지**

**보고도 그대로 옮기면 안 되는 것**

| Figma 에서 | 앱에서는 |
|---|---|
| 색을 스포이드로 뽑기 | ❌ **금지.** `TmtnColor.*` 에서 가져옵니다. Figma 값과 다르면 **토큰이 맞습니다** |
| `17px` 같은 글자 크기 | ❌ 7단계(`TmtnText.*`) 중 **가장 가까운 것**으로 올림 |
| `x:24 y:312` 절대 위치 | ❌ `Column`/`Row` + `TmtnSpace`. 절대 위치를 쓰면 글자를 키운 기기에서 겹칩니다 |
| 고정 높이 박스 | ❌ 내용에 따라 늘어나게. 높이를 박으면 두 줄이 되는 순간 잘립니다 |

Figma 는 **한 기기 · 한 글자 크기**로 그린 정지 화면입니다. 그대로 좌표를 옮기면 다른 기기에서 깨집니다.

### 3단계 — Figma 에 **없는** 것을 채운다 (여기가 진짜 작업)

정지 화면 한 장에는 이게 안 들어 있습니다. 만들기 전에 네 가지를 먼저 정하세요.

1. **값이 어디서 오나**
   `TodayViewModel` 에 이미 있나? `missions.json` 인가? `TmtnStore` 인가? 아직 없으면 목업으로 둘 것인가?
2. **상태가 몇 갈래인가**
   불러오는 중 · 비어 있음 · 실패 · 권한 거부. 껍데기(H01~H07)는 이미 있으니 **가져다 쓰면 됩니다**
3. **어디로 넘어가나**
   `ui/nav/Routes.kt` 에 라우트를 더하고 `TmtnApp.kt` 에 연결. **뒤로 가기를 눌렀을 때 어디로 가는지**까지 정하세요
4. **도메인 규칙에 걸리는 게 있나**
   위 **3장 "손대면 안 되는 것"** 을 먼저 읽으세요. 쉼·주황·달력 선 종류가 특히 자주 걸립니다

### 4단계 — 만들고, 실기기로 확인한다

에뮬레이터로는 안 잡히는 게 많습니다. **반드시 실기기**로 보세요.

- [ ] 시스템 **글자 크기를 가장 크게** 놓고 넘치거나 잘리지 않는가
- [ ] 누를 수 있는 것이 **최소 48dp** 인가
- [ ] 스크롤 없는 화면이면 **본문 632dp** 안에 들어오는가 (390×844 기준)
- [ ] `adb logcat -b crash` 에 `FATAL` 이 없는가

> **빌드 통과 ≠ 안 죽음.** 카드 앞면이 음수 패딩으로 죽은 걸 빌드로는 못 잡았습니다.
> 화면을 새로 만들면 **반드시 한 번은 실기기로 열어 보세요.**

### 먼저 확인할 것

Figma 파일 `ByGT2uoinUBxAQOBqAK7sM` **접근 권한이 있어야** 링크가 열립니다.
없으면 1단계부터 막히니 시작 전에 확인하세요.
