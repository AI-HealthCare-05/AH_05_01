# 최종 UI에 SHAP·XAI 반영 — 2026-09-16

이 폴더의 `index.html`을 열면 외부 서버 없이 화면을 확인할 수 있습니다. Android 구현은 상위 프로젝트의 `android/app/src/main`에 반영했습니다. HTML은 가상 미션 기록과 기존 실모델로 계산한 가상 설문 7개를 사용하는 화면 검토본입니다.

## 반영한 화면

- 주간면은 월요일~일요일. 아직 오지 않은 날짜는 선택할 수 없습니다.
- 기록은 완료 미션명·완료일로 보여줍니다. 미션에서 운동 시간을 추정하거나 설문 운동량에 합산하지 않습니다.
- 일간 읽을거리 1개, 주간 읽을거리 서로 다른 주제 2개. 호의 날짜로 순서를 섞어 같은 호의 글이 새로고침마다 바뀌지 않습니다. 단, 승인·출처가 만료되거나 카탈로그가 바뀌면 다시 선택합니다.
- ‘꾸준함에 관하여’는 주간면에 유지합니다.
- 상단 새로고침, 섹션 번호 배지, 카드 추천 이유 진입, 사용자 화면의 검토용 문구를 제거했습니다. 실패한 항목의 ‘다시 불러오기’는 남겼습니다.
- 재료명은 나뭇가지·받침돌·물길·다짐흙·새잎으로 통일했습니다. 예전 서버가 ‘숯’을 내려줘도 해당 근력 재료는 받침돌로 표시합니다.
- 최신 수채화 재료 아이콘을 사용하고, 댐과 비버가 겹치던 주간 삽화는 하나의 새 장면으로 교체했습니다. `ContentScale.Fit`으로 그림 전체를 보여줍니다.
- 허리둘레는 홈의 별도 영역에 유지하고 일보에 표시하지 않습니다. 기존 홈의 신문 진입 디자인을 유지했습니다.
- 화면 설명은 기존 모션 토큰으로 짧게 펼칩니다. 숫자·비교 막대는 움직이지 않습니다. 동작 줄이기와 키보드 입력에서는 즉시 전환합니다.

## SHAP·XAI 동작

1. 점수는 기존 `/tuntun-score/peer/v2` 응답을 사용합니다. 기존 종합지수 공식과 영역 순위를 대체하지 않습니다.
2. `/tuntun-score/personal`은 로그인한 사용자의 최신 신체·운동 설문으로 SHAP와 또래 활동 비교를 준비합니다. 계산 중에도 준비된 활동 비교는 먼저 읽을 수 있습니다.
3. 당뇨·고혈압의 계산 설명은 **입력 식별자, 기준일, 모델 버전, 영역의 내부 참고점수, 등수**가 현재 점수와 일치할 때만 연결됩니다. 예전 서버 응답이나 서로 다른 결과를 끼워 맞추지 않습니다.
4. 화면에는 활동 비교와 챌린지 안내를 보여주고, SHAP는 ‘내 정보가 계산에 어떻게 쓰였을까요?’를 눌러 펼칩니다. 나이·성별을 바꿔야 할 챌린지 목표로 안내하지 않습니다.
5. 하루 카드 상태와 서버가 알려준 틈새운동 남은 횟수에 맞춰 안내합니다. 하루 카드 완료 전에는 틈새운동을 권하지 않고, 추가 2회를 채웠으면 더 하라고 안내하지 않습니다.
6. KNHANES 2019~2021 집단 통계와 개발 배경 표본 300건의 역할을 구분합니다. 출처·계산 근거는 펼쳐서 볼 수 있습니다.

## 실제 서버에서 켜기 전에 필요한 것

**이번 작업에서 원격 서버 배포·실계정 DB 연결·개인별 모델 재계산은 실행하지 않았습니다.** 화면과 연결 코드, 데이터 검증, 빌드까지 완료한 상태입니다.

- 기존 모델 배포물과 그 배포물에 맞는 Python 실행 환경을 별도로 준비합니다. `model_service/personal_shap.py`의 파일 해시 검사에 맞아야 합니다. 모델 파일·KNHANES 원자료·API 키는 이 폴더에 넣지 않았습니다.
- 개인 모델 작업 서버의 주소와 인증 토큰은 서버 실행 환경의 `TUNTUN_XAI_URL`, `TUNTUN_XAI_TOKEN`으로 주입합니다. 앱이나 HTML에 넣지 않습니다.
- 개발 환경에서는 아래 실행 도구가 임시 인증 토큰을 생성해 API와 작업 서버에만 전달합니다. 실행 전에 기존 DB와 또래 점수 브릿지가 설정되어 있어야 합니다. 경로는 실제 준비한 경로로 바꿉니다.

```powershell
python -m model_service.run_local_review --runtime "<모델 환경의 python.exe>" --payload "<waist_cm.py가 있는 모델 배포 폴더>" --api-port 8000
```

- 이번 연결에는 새로운 DB 컬럼이나 마이그레이션이 필요하지 않습니다. 최종 앱에서 이미 확인한 근력운동 ‘일수’ 계약을 사용합니다. 다른 기능의 기존 마이그레이션은 별도로 유지하세요.
- `app/data/journal/approvals.json`은 아직 승인 기록이 비어 있습니다. **실제 앱 API에서는 승인 전 글을 공개하지 않습니다.** HTML에 보이는 40개 출처 문장은 오프라인 검토용입니다. 담당자가 본문 해시·출처 버전·사용 권한·적용 연령을 확인하고 실제 승인 기록을 작성해야 합니다. 화면의 ‘검토용’ 배너 삭제로 공개 승인을 대신하지 않았습니다.
- 개인 모델의 기존 `ENV=prod` 공개 제한도 유지했습니다. 운영 허용 여부는 모델 배포 검토에서 결정해야 합니다. 임의로 환경을 바꿔 우회하지 마세요.
