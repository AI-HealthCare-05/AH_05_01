# EC2에서 SHAP·XAI를 제공하려면

2026-09-16, PR #19 코드와 저장소 배포 설정 기준입니다. 실제 EC2의 실행 명령·인스턴스 사양·환경 변수 값은 확인하지 않았습니다.

## 먼저 알아둘 점

**현재 앱의 개인 SHAP 계산, 또래 활동 비교, 챌린지 안내, 승인된 읽을거리 표시는 외부 생성형 AI API 키 없이 동작합니다.**

| 기능 | 필요한 것 | 외부 AI API 키 |
|---|---|---|
| 당뇨·혈압 개인 SHAP | 실제 학습 모델, 동일 전처리·버전, 배경 표본, 모델 실행 환경 | 불필요 |
| 나이대·성별 활동 비교 | 사용자 운동 설문, 포함된 KNHANES 집단 통계 JSON | 불필요 |
| 챌린지 동기부여 문구 | 검증된 계산 결과와 하루 카드·틈새운동 상태, 코드의 문장 규칙 | 불필요 |
| 식탁·움직임 등 읽을거리 표시 | 본문·출처·공개 승인 목록 | 불필요 |
| 새 읽을거리 초안 작성·검색 보조 | 별도 로컬 작업실의 LLM·임베딩 연결, 근거 메모 | 해당 제공업체 API 키 필요 |

이전 로컬 작업실에 설정한 OpenAI 연결과 앱 서버의 SHAP 연결은 별개입니다. PR #19는 로컬 작업실 자체를 EC2 편집 서비스로 배포하는 패키지가 아닙니다. OpenCode에서 받은 키라면 OpenAI 키로 바로 대입하지 말고 제공업체·API 주소·사용 가능한 모델을 먼저 확인합니다. 키 값은 GitHub·앱·HTML에 넣지 않습니다.

## EC2에 준비할 것

1. **같은 버전의 모델 배포물**: `waist_cm.py`, `01_inference/`, `02_background/background_300.csv`. 단일 모델 파일만 복사하는 방식은 부족합니다. `model_service/personal_shap.py`가 원본 파일 해시와 하위 배포물 무결성을 검사합니다. 기존 점수 브릿지와 모델·정규화·참고점수·기준일이 맞아야 화면에 설명이 연결됩니다.
2. **분리된 Python 실행 환경**: 앱 API는 Python 3.13 계열, 현재 모델 배포물은 별도의 Python 3.14 계열 환경을 전제로 합니다. `shap==0.49.1` 검사와 모델이 요구하는 NumPy·pandas·scikit-learn 등 버전을 만족하는 Linux 환경을 재현·검증해야 합니다. Windows 가상환경 폴더를 EC2에 복사해서 쓰지 않습니다. 기존 peer 브릿지 requirements에는 SHAP가 없어 그대로 재사용하는 것만으로는 부족합니다.
3. **개인 SHAP 작업 서버**: `model_service/server.py`를 장기 실행하고 재시작·자원 제한·상태 확인을 구성합니다. 현 코드는 CPU 계산이며 GPU 코드는 없습니다. 필요한 RAM·CPU 수는 실제 모델 로딩과 동시 요청을 측정해 결정합니다.
4. **서버 사이 연결 설정**: FastAPI에 `TUNTUN_XAI_URL`, FastAPI와 작업 서버 양쪽에 같은 `TUNTUN_XAI_TOKEN`을 주입합니다. 토큰은 최소 32자이며 외부 AI 제공업체의 API 키와 다릅니다. EC2의 Secrets Manager 등에서 서버로만 전달할 수 있습니다.
5. **사용자 입력과 동의**: 기존 DB의 생년월·성별·키·몸무게·운동 설문과 분석 동의가 필요합니다. 새 운동 시간 수집은 필요하지 않으며, 완료 미션으로 설문 운동량을 바꾸지 않습니다.
6. **읽을거리 공개 승인**: `app/data/journal/knowledge.json`, `sources.json`은 포함되어 있으나 `approvals.json`은 비어 있습니다. 본문·출처·사용 범위 확인 후 승인 기록을 작성해야 실제 API에서 글을 제공합니다. 신뢰할 근거가 없는 글을 API 키로 자동 승인하지 않습니다.

일반 사용자에게 앱을 제공하기 전에는 HTTPS, 분석 동의와 개인 응답 처리, 모델 적용 대상·검증 결과도 함께 확인합니다.

## 현재 코드에서 배포 전에 남은 작업

| 확인한 상태 | 필요한 작업 |
|---|---|
| API Dockerfile이 `app/`만 복사하여 `model_service.activity_reference` import를 해결하지 못함 | 이번 후속 수정에서 `COPY ./model_service ./model_service` 추가. 컨테이너 이미지 재빌드 필요 |
| 저장소 Compose에 기존 점수 브릿지는 있지만 개인 SHAP 서비스는 없음 | 모델 전용 이미지·실행 서비스·배포물 읽기 전용 마운트 구성 |
| SHAP 서버가 `127.0.0.1`에만 바인딩 | 별도 컨테이너라면 기존 브릿지와 같이 `network_mode: service:fastapi`를 쓰는 구성을 검토. 이때 API URL은 `http://127.0.0.1:8776`, 외부 포트 공개 불필요. 일반 bridge 네트워크의 서비스명 연결은 현재 loopback 바인딩 그대로는 동작하지 않음 |
| 운영 FastAPI 기본 실행은 worker 3개, SHAP 작업·결과는 프로세스별 메모리 | 다중 프로세스에서 같은 계산이 중복되지 않고 결과 조회가 일관되도록 공유 작업 큐·캐시 설계 필요. 기존 Redis를 사용할 수 있으나 현재 SHAP 코드에는 아직 연결되지 않음. 격리 검토 환경에서 worker 1개로 기능 확인하는 것과 운영 용량 설계는 구분 |
| `ENV=prod`이면 개인 API가 `release_review_required` 반환 | 모델 공개 검토 후 명시적인 운영 활성화 정책을 구현·검증. 운영 서버를 `ENV=local`로 바꿔 우회하지 않음 |
| `run_local_review.py`는 `ENV=local`을 지정하는 로컬 도구 | 운영 시작 명령으로 사용하지 않음 |

위 Compose 제안은 아직 적용한 배포 설정이 아닙니다. 저장소에는 루트 `docker-compose.prod.yml`과 `infra/docker/docker-compose.prod.yml` 두 경로가 있으므로 **EC2에서 실제 사용하는 파일을 먼저 확인**해야 합니다.

## 담당자에게 전달할 내용

> PR #19의 앱·서버 변경을 검토해주세요. 개인 SHAP는 생성형 AI API 키가 아니라, 현재 점수와 같은 모델 배포물 및 별도 SHAP 작업 서버가 필요합니다. 실제 EC2 Compose 경로와 인스턴스 CPU/RAM을 확인한 뒤 모델 실행 환경·내부 통신·작업 큐를 맞춰주세요. 모델 운영 공개 검토와 읽을거리 승인 목록도 필요합니다. 운영 환경을 local로 바꾸는 우회는 하지 않습니다. 첫 댐 복구 DB 마이그레이션은 SHAP와 별도 변경입니다.

확인에 필요한 정보는 **EC2 인스턴스 종류·운영체제, 실제 Compose 파일/실행 명령, 기존 모델 브릿지 동작 여부, 모델 배포물 위치**입니다. 비밀번호나 API 키 값을 대화에 보낼 필요는 없습니다.
