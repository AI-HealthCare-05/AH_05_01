# 틈튼 요구사항 정의서

버전 2.0 · 2026-09-15 · [PRD](PRD.md)의 현재 개발 범위에 대응

## 1. 읽는 방법

과거 문서의 FR/NFR ID를 유지하되, 변경되거나 폐기된 요구를 아래에 명시했다. 옛 문서의 체크 표시를 그대로 옮기지 않았다. **수용 기준은 앞으로 검증할 기준을 포함하며, 표의 모든 항목이 시험 통과했다는 뜻이 아니다.**

| 상태 | 의미 |
| --- | --- |
| 코드 | 현재 실행 경로·상수·DTO에서 확인. 운영 E2E 통과는 별개 |
| 부분 | 경로는 있지만 일부 요구·플랫폼·실제 연동 검증이 남음 |
| 후속 | 이번 대조로 충족을 확인하지 못했거나 별도 제품·기술 결정 필요 |
| 대체 | 예전 기준을 현재 기준으로 변경. 과거 동작을 복원하지 않음 |
| 제거 | 사용자 결정으로 현재 제품 범위에서 제외 |

P0는 출시·데이터 정확성에 필요한 항목, P1은 핵심 사용 완성도, P2는 후속 개선이다. 이 우선순위는 구현 완료율을 뜻하지 않는다. 근거 번호는 문서 끝의 파일 지도와 연결된다.

## 4. 이번 개정에서 확인한 시험 근거와 남은 시험

**기존 동일 Android 소스의 시험:** 단위 83개, 별도 검증 앱 기기 58개, 빌드 성공. A16 요일 128가지 조합·0일 강도·5~7일 매핑·유산소 필드 보존, 좁은 폭·글자 확대, 긴 제목·센서 및 오류 흐름을 포함한다. 전체 요구사항 100% 완료율로 환산하지 않는다. 문서 개정 중 앱 시험을 새로 실행한 결과가 아니다.

다음은 팀 연결 환경의 우선 수용 시나리오다.

| 시나리오 | 확인할 결과 |
| --- | --- |
| 새 이메일·기존 계정·Google 신규/연결 | 실제 서버·메일·OAuth 결과에 따라 이동하고 실패 상태 유지 |
| 근력 0 / 3 / 7일 후 재진입 | 0/null, 3/강도, 5/강도의 기존 계약. 7일의 요일 복원은 안 된다고 안내 |
| 카드 확정 더블탭·완료 재전송 | 한 장 선택 유지, 재료 중복 없음 |
| 오늘 카드 미완료·완료 후 틈새 운동 | 미완료 시 차단, 완료 후 최대 2개 보상, 3번째 거절 |
| 권한 거부·미지원·앱 종료·다시 열기 | 대체·복구·동기화 상태와 서버 기록 일치 |
| 자정·월 변경·가입 이전·쉼 취소 | 날짜·횟수·달력·홈·일보 일관성 |
| peer 동의 거부·모델 미설정 | 403/503에 맞는 안내, 샘플 점수로 바뀌지 않음 |
| 허리 결과 없음·과거 성공 후 실패 | 0cm로 표시하지 않음, 과거 계산일·최신 입력 여부를 혼동하지 않음 |
| 데이터 삭제·CSV 내보내기 | 실제 삭제 범위·포함 필드·파일 저장·실패 안내 확인 |
