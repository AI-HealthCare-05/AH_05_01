## 문서별 역할

제품 규칙은 PRD에서 관리한다. 요구사항 정의서는 해당 규칙의 구현 상태와 수용 기준을, 유저 플로우는 이동과 실패 분기를 관리한다. 숫자·API를 바꿀 때 세 문서에 서로 다른 정책을 추가하지 않는다. 실제 DTO·라우터와 충돌하면 차이를 이슈로 기록하고 제품 결정을 거쳐 갱신한다.

`코드 확인`은 실행 경로를 읽었다는 뜻이다. `기기 검증`도 명시된 시나리오에 한정한다. 운영 API 연결, 모델 승인·배포, 실외 센서 정확도, 실제 Google 로그인까지 통과했다는 의미로 사용하지 않는다.

과거의 107개 화면 번호, 예전 점수 구간, 고정 높이 화면 명세는 현재 기능을 재생성하는 근거로 쓰지 않는다. 특히 **Figma A16 근력운동 요일 선택**은 코드의 `A08_EXERCISE`에 반영돼 있다. 코드의 `A16_PERMISSIONS`는 권한 안내 단계다.

## 갱신 방법

1. 변경 PR과 앱·서버 기준 커밋을 기록한다.
2. 제품 규칙 또는 상태가 바뀐 문서를 수정한다. 없어진 기능은 제거 사실과 대체 경로를 남긴다.
3. 근거 코드와 검증 범위를 연결하고 미검증 항목을 따로 적는다.
4. 관련 화면·요청 필드·상태 전이가 함께 맞는지 확인한다.
