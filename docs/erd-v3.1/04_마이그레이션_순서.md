# 04 · 마이그레이션 순서

113개 테이블을 한 번에 넣으면 FK 때문에 깨집니다. **6단계로 나눕니다.**
각 단계가 끝날 때마다 앱이 어디까지 동작하는지도 같이 적었습니다.

---

## 0단계 — `users` 충돌 먼저 (다른 것보다 먼저)

161개 FK 중 **대부분이 `users.id` 를 봅니다.** 여기가 흔들리면 전부 다시 해야 합니다.

```sql
-- ddl/v3.1_patch.sql 의 PATCH 1
```

| 무엇 | 왜 |
|---|---|
| `email` 에 UNIQUE 추가 | **지금 없습니다. 동시 가입으로 중복 계정이 생길 수 있는 버그** |
| `birthday DATE` → `birth_year` + `birth_month` | A07이 연·월만 받음 |
| `phone_number` 삭제 | 가입 흐름 어디에도 없음 |
| `nickname` + `display_name` 추가 | A07이 이름·닉네임 둘 다 받음 |
| `status` 추가 | 탈퇴 유예(`DELETION_PENDING`) 표현 |

> 지금 저장소에 실사용자 데이터가 없으니 **부담 없이 바꿀 수 있는 유일한 시점**입니다.
> 나중에 하면 데이터 마이그레이션이 붙습니다.
