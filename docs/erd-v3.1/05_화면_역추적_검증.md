# 05 · 화면 역추적 검증 — 107화면이 요구하는 데이터가 다 나오나

v3.0의 화면 추적표는 **66화면 기준**이었습니다.
v5에서 늘어난 41화면을 하나씩 역추적해 **"이 화면의 숫자가 어느 테이블에서 나오는가"** 를 확인했습니다.

**결과: 107화면 중 103개는 나옵니다. 4개가 안 나옵니다.**

---

## 안 나오는 것 4개 ★

### ① `A04` 이메일 인증번호 · `A11` 인증번호 오류 — **테이블 없음**

화면에 이렇게 적혀 있습니다.

> 남은 시도 **3회 중 1회 사용** · 5회를 넘기면 잠시 후 다시 시도할 수 있습니다
> 남은 시간 **4:32** · 인증번호 다시 받기

그런데 스키마에 **이메일 인증 코드를 담을 곳이 없습니다.**
`auth_identities` 는 `provider` / `provider_user_id` / `linked_at` 뿐이고,
`password_reset_requests` 는 **비밀번호 재설정 전용**입니다.

가입 자체가 막히는 자리라 **1단계에서 반드시 필요합니다.** → `ddl/v3.1_patch.sql` PATCH 6-①

### ② `F15` 이메일 변경 — **테이블 없음**

새 주소로 인증번호를 보내고, 확인되기 전까지는 **기존 주소를 유지**해야 합니다.
①의 테이블에 `purpose` 를 두어 같이 처리하는 게 깔끔합니다. → PATCH 6-①

### ③ `B14` · `B14b` 첫 진입 코치마크 — **본 적 있음 플래그 없음**

`user_profiles.onboarding_step` 은 `DONE` 까지만 있고 **코치마크를 봤는지는 안 남습니다.**
앱에 저장하면 기기를 바꾸거나 지웠다 깔면 다시 뜹니다. → PATCH 6-②

### ④ `B11` 대체 미션 요청 — **이유가 안 남음**

화면에서 4개 중 하나를 고릅니다 — 시간이 없어요 / 장소가 마땅치 않아요 / 몸이 무거워요 / 날씨가 안 맞아요.
`daily_challenges.substituted_from_option_id` 는 "무엇에서 바꿨나"만 남기고 **왜 바꿨는지는 안 남습니다.**

이 4개가 쌓이면 **"이 사용자에게는 실내 미션을 더 주자"** 같은 추천 조정의 근거가 됩니다.
지금 안 남기면 나중에 소급이 안 됩니다. → PATCH 6-③

설계가 앞서간 부분입니다. **지우지 말고 두되, 지금 만들지는 마세요.**

| 테이블 | 상태 |
|---|---|
| `rhythm_types` `rhythm_type_results` | v3.0 ⑫ 항목. **Figma v5에도 화면 없음.** 미사용 |
| `choice_scenarios` `choice_prompts` `choice_responses` | 선택형 설문. 화면 없음 |
| `share_preferences` `share_events` | 공유 기능. v5 화면 없음 (담당표 12번 "아직 없음 P1") |
| `experiments` 4종 | A/B 실험. 해커톤 범위 밖 |
| `health_connect_links` `health_connect_sync_logs` | Health Connect 연동. `F03`에 자리는 있으나 흐름 미정 |

**114개 중 실제로 v5가 쓰는 것은 약 90개**, 나머지 24개는 나중을 위한 자리입니다.
1~4단계(65개)만 넣어도 해커톤 시연 동선은 전부 돕니다.
