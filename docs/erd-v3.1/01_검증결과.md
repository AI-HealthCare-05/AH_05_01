## 3. ⚠️ 재료 라벨 — 데이터와 디자인이 어긋나 있습니다

v3.0 문서가 "⑩ 金(새잎)의 뜻"으로 남겨 둔 미결 사항인데, **앱에 실제로 들어간 데이터를 열어 보니 상황이 더 구체적입니다.**

### 앱 `missions.json` 200장의 실제 배정

| 오행 | 재료 | 앱 데이터의 `area` | 장수 |
|---|---|---|---|
| 木 WOOD | 나뭇가지 BRANCH | 유산소 | 40 |
| 火 FIRE | 받침돌 STONE | 근력운동 | 40 |
| 土 EARTH | 다짐흙 SOIL | **식사·수면·생활 리듬** | 40 |
| 金 METAL | 새잎 LEAF | **기록** | 40 |
| 水 WATER | 물길 WATERWAY | 수분·회복 | 40 |

### Figma v5 `G02 재료 도감`의 라벨

| 재료 | Figma 라벨 |
|---|---|
| 나뭇가지 | 움직임 · 유산소 ✅ |
| 받침돌 | 근력 ✅ |
| 물길 | 수분 ✅ |
| 다짐흙 | **생활리듬** |
| 새잎 | **식사·기록** |

### 무엇이 문제인가

**"식사"가 두 군데에 있습니다.**
데이터에서는 식사 미션이 `土(다짐흙)` 에 들어가 있는데, Figma는 `새잎 = 식사·기록` 이라고 써 두었습니다.
사용자가 식사 미션을 완료하면 **다짐흙**을 받는데 도감에는 **새잎**이 식사라고 적혀 있습니다.

### 권하는 해결 — Figma 글자 2개만 고치기

| 재료 | 지금 Figma | 바꿀 라벨 |
|---|---|---|
| 다짐흙 | 생활리듬 | **식사 · 생활리듬** |
| 새잎 | 식사·기록 | **기록** |

- 데이터 이동 **0건**. CSV 200장 그대로.
- 고칠 곳은 Figma `G01` `G02` 와 앱의 재료 캡션 몇 군데.
- v3.0이 제시한 "길 B"(기록 40장을 土로 옮기기)보다 훨씬 쌉니다.

> 반대로 **"새잎은 식사여야 한다"** 가 기획 의도라면 CSV 40행의 축을 옮겨야 합니다.
> 지현님이 한 번만 정해 주시면 그 뒤로는 UPDATE 한 번 또는 Figma 수정 한 번으로 끝납니다.

## 4. 앱 `missions.json` 용어가 ERD와 다릅니다

같은 것을 다른 이름으로 부르고 있어서, 서버 연동할 때 매핑 표가 필요합니다.

| 뜻 | 앱 JSON | ERD / API |
|---|---|---|
| 오행 축 | `axis` (`WOOD`) | `element_code` (`WOOD`) — 값은 같음 |
| 축 이름 | `axisLabel` (`뻗는 기운`) | `elements.label_ko` |
| 영역 | `area` (`유산소`) | `domain_code` |
| 측정 방식 | `type` | `measure_type` — 값 5종 동일 ✅ |
| 보상 재료 | `rewardMaterial` (`BRANCH`) | `elements.material_code` |
| 미션 문구 | `action` + `lineTemplate` | `action_text` + `one_liner_template` |
| 목표 범위 | `numMin` `numMax` `numStep` | `number_min` `number_max` `number_step` |

**값은 대부분 같고 이름만 다릅니다.** camelCase ↔ snake_case 매핑 한 장이면 됩니다.
`ddl/v3.1_patch.sql` 의 PATCH 3에 매핑 뷰를 넣어 두었습니다.

### 측정 방식 분포 (200장)

| `measure_type` | 장수 | 자동 측정? |
|---|---|---|
| `SELF_CHECK` | 125 | 아니오 |
| `SELF_TIMER` | 42 | 아니오 |
| `MODEL_ACTIVE_TIME` | 17 | 예 |
| `MODEL_STAIR_COUNT` | 10 | 예 |
| `MODEL_DISTANCE` | 6 | 예 |

자동 측정이 필요한 미션은 **33장(16.5%)** 뿐입니다.
박강호님 모델이 늦어져도 **나머지 167장으로 시연이 됩니다.** 일정상 중요한 숫자입니다.

## 5. API 경로 충돌 (v3.0 ⑤ 항목, 아직 미해결)

| | 저장소 지금 | 계약서 | ERD v3.0 결정 |
|---|---|---|---|
| 가입 | `/api/v1/auth/signup` | `/v1/auth/sign-up` | **`/api/v1/auth/sign-up`** |
| 토큰 갱신 | `GET /auth/token/refresh` | `POST /v1/auth/refresh` | **`POST /api/v1/auth/refresh`** |

`GET` 으로 토큰을 갱신하면 URL이 로그·브라우저 기록에 남습니다. **`POST` 로 바꾸는 게 맞습니다.**
