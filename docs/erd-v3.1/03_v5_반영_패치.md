## 보정 1 — `rest_days.source` 추가

v5에서 쉼을 표시할 수 있는 곳이 **두 군데**가 됐습니다.

| 경로 | 화면 |
|---|---|
| 홈에서 오늘을 쉼으로 | `B01` `B01b` `B06` `C01` → `B16` 확인 → `B17` |
| 달력에서 지난 날짜를 쉼으로 | `D01` → `D03` → `D06` |

어느 쪽으로 쉬는지 알면 나중에 **"쉼 버튼을 홈에 둔 게 효과가 있었나"**를 답할 수 있습니다.

```sql
ALTER TABLE rest_days
  ADD COLUMN source ENUM('HOME','CALENDAR','SYSTEM') NOT NULL DEFAULT 'HOME'
    COMMENT 'B16 홈 / D06 달력 / 시스템 자동' AFTER reason_code;
```

## 보정 2 — 쉼 취소를 어떻게 남길 것인가

`B17`에서 "그래도 미션 해볼래요"를 누르면 그날의 쉼이 풀립니다.

**행을 지우면 안 됩니다.** 지우면 "쉼 2번 다 썼다가 하나 취소해서 다시 1번 남았다"는 흐름이
기록에 안 남고, 주 2회 상한을 악용하는지도 볼 수 없습니다.

```sql
ALTER TABLE rest_days
  ADD COLUMN cancelled_at DATETIME NULL COMMENT 'B17에서 쉼 취소' AFTER marked_at;

-- UNIQUE 를 살아 있는 행에만 걸려면 MySQL 8 에서는 이렇게
ALTER TABLE rest_days DROP INDEX uk_rd;
ALTER TABLE rest_days
  ADD COLUMN is_active BOOLEAN
    GENERATED ALWAYS AS (CASE WHEN cancelled_at IS NULL THEN 1 ELSE NULL END) VIRTUAL,
  ADD UNIQUE KEY uk_rd_active (user_id, service_date, is_active);
```

> `is_active` 가 취소된 행에서 `NULL` 이 되고, **MySQL 의 UNIQUE 는 NULL 을 중복으로 안 봅니다.**
> 그래서 같은 날짜를 쉼 → 취소 → 다시 쉼 해도 들어갑니다. 살아 있는 쉼은 날짜당 하나뿐이고요.

**주 2회 상한을 셀 때는 `cancelled_at IS NULL` 만 셉니다.**

```sql
SELECT 2 - COUNT(*) AS remaining
FROM rest_days
WHERE user_id = ? AND week_key = ? AND cancelled_at IS NULL;
```

## 보정 3 — 주 상한값을 상수로 박지 마세요

지금은 "주 2회"가 주석에만 있습니다. 기획이 3회로 바꾸면 코드를 뒤져야 합니다.

```sql
CREATE TABLE rest_policies (
  policy_key   VARCHAR(40)      NOT NULL,
  weekly_limit TINYINT UNSIGNED NOT NULL DEFAULT 2,
  effective_from DATE           NOT NULL,
  note         VARCHAR(200)     NULL,
  PRIMARY KEY (policy_key, effective_from)
) ENGINE=InnoDB COMMENT='쉼 주당 상한. 바뀌어도 과거 주는 그때 값으로 판정';

INSERT INTO rest_policies VALUES ('DEFAULT', 2, '2026-01-01', 'Figma v5 · 한 주에 두 번까지');
```

`effective_from` 을 두는 이유 — 상한을 3으로 올려도 **지난주 리포트는 그때 기준으로 남아야** 하기 때문입니다.

## 미완료(MISSED)는 저장하지 않습니다

v5에서 미완료가 다시 독립 상태가 됐지만, **테이블을 만들지 마세요.**

```
미완료 = 오늘보다 이전 날짜
         AND daily_challenges 에 COMPLETED 없음
         AND rest_days 에 없음
```

저장하면 자정마다 배치를 돌려야 하고, 시간대가 다른 사용자에서 반드시 틀어집니다.
**계산으로 내는 게 맞습니다.** 달력 API가 한 달치를 한 번에 계산해 내려주면 됩니다.

```sql
-- D01 월 캘린더 한 달치
SELECT d.service_date,
       CASE
         WHEN r.id IS NOT NULL                     THEN 'REST'
         WHEN c.status = 'COMPLETED'               THEN 'DONE'
         WHEN d.service_date > CURRENT_DATE        THEN 'UPCOMING'
         WHEN d.service_date = CURRENT_DATE        THEN 'TODAY'
         ELSE 'MISSED'
       END AS day_state
FROM (/* 그 달의 날짜 목록 */) d
LEFT JOIN daily_challenges c
       ON c.user_id = ? AND c.service_date = d.service_date
LEFT JOIN rest_days r
       ON r.user_id = ? AND r.service_date = d.service_date AND r.cancelled_at IS NULL;
```

## 앱이 새로 요구하는 API 2개

| 화면 | 필요한 것 | 제안 |
|---|---|---|
| `B16` 쉬어가기 확인 | 이번 주 남은 쉼 횟수 | `GET /api/v1/records/rest-quota` → `{used:1, limit:2, week_key:"2026-W35"}` |
| `B17` 오늘은 쉼 | 쉼 등록 / 취소 | `POST /api/v1/records/rest-days` · `DELETE /api/v1/records/rest-days/{date}` |

`DELETE` 는 실제로 지우지 말고 `cancelled_at` 을 채우세요.
