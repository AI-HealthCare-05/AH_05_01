# 화면 명세

Figma 는 **"어떻게 생겼나"** 만 알려 줍니다.
개발에 정작 필요한 **"무슨 값이 들어가고 · 언제 갈라지고 · 어디로 넘어가나"** 는 없습니다.

이 폴더는 그 빈칸을 채운 문서를 화면 단위로 모읍니다.
**명세 한 장 = 화면 하나**이고, 그 안에 **붙여넣으면 바로 도는 Compose 뼈대**가 같이 들어 있습니다.

---

## 왜 뼈대까지 주는가

이 앱은 디자인이 이미 **코드로 잠겨** 있습니다.

- 색 `TmtnColor.*` · 글자 `TmtnText.*` · 간격 `TmtnSpace.*` · 모서리 `TmtnShape.*`
- 공통 부품 16개 (`TmtnTopBar` `TmtnCardBox` `NoteBox` `TmtnFilledButton` `StatusBadge` …)

그래서 **Figma 를 보고 색·크기를 다시 재는 일이 필요 없습니다.**
부품을 순서대로 쌓으면 그게 곧 v5 디자인입니다. 명세의 뼈대는 그 조립을 미리 해 둔 것입니다.

받는 사람은 **뼈대를 붙여넣고 → 값을 연결하고 → 실기기로 확인**하면 됩니다.

---

## 쓰는 법

### 명세를 만드는 쪽

1. [`_템플릿.md`](_템플릿.md) 를 복사해 `<코드>_<화면이름>.md` 로 저장합니다 (예: `G06_카드첩.md`)
2. [`../design-v5/index.html`](../design-v5/index.html) 에서 화면 코드를 눌러 Figma 를 엽니다
3. [`../design-v5/SCREENS.csv`](../design-v5/SCREENS.csv) 에서 그 화면 행의 `appbar` · `primary_cta` · `bottom_nav` · `overlay` 를 그대로 옮겨 적습니다 — **문구를 새로 짓지 않습니다**
4. 1~5절(값 · 상태 · 이동 · 규칙)을 채웁니다. **여기가 진짜 일입니다**
5. 6절 뼈대를 화면 모양에 맞게 손봅니다

### 명세를 받는 쪽

1. 6절 뼈대를 새 파일로 붙여넣습니다
2. `TODO` 자리에 2절의 값을 연결합니다
3. `Routes.kt` · `TmtnApp.kt` 에 4절의 라우트를 답니다
4. 7절 체크리스트를 **실기기**로 확인합니다
